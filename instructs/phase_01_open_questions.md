# Phase 01 Open Questions

## Unresolved Ambiguities

- Is the future demo expected to preserve the current simulation-based causal stage, or is that stage only a temporary research proxy until real intervention/outcome data exists?
- Which saved churn pipeline should be treated as the intended canonical one later:
  - the logic in `Save_Model.ipynb`
  - the nearly duplicated logic in `5_CAI_P_Post_Generated.ipynb`
  - or a future clean reimplementation extracted from both?
- Is the heavy embedding/GPU clustering path intended to remain first-class, or should future phases assume a CPU-first default with optional GPU extras?
- Is the nested repo layout intentional long-term, or only an artifact of how the project was copied into the current workspace?

## Assumptions Future Phases Must Remember

- Assumption: the repo is currently a research/demo bundle, not a maintainable platform.
- Assumption: there is no reliable source of truth outside notebooks in the current codebase.
- Assumption: raw data most likely starts from `Data/train.csv` and `Data/test.csv`.
- Assumption: files in `Data/data from remote sever/` are mostly working exports/intermediate artifacts rather than preferred long-term canonical storage.
- Assumption: future target product direction is a local Python demo platform with:
  - uploads of new customer data
  - validation/profiling
  - churn + segmentation + recommendation
  - diagnostics/process tracking
  - Excel export for sales
  - local stack direction around Docker, Postgres, and Streamlit

## Risks of Misinterpreting Current Logic

- Risk: treating notebook outputs as if they were generated by a clean reproducible pipeline when some notebooks depend on hidden state.
- Risk: treating current evaluation metrics as production-grade estimates despite signs of leakage or same-data evaluation in some notebooks.
- Risk: treating `df_causal_ai` as a directly observed real-world causal training table when it appears to be downstream of simulated treatment/post-outcome logic.
- Risk: assuming duplicated CSVs represent independent data assets when some were observed to be byte-identical duplicates.
- Risk: assuming every cell in notebook 3 is part of the intended pipeline even though some branches are experimental, incomplete, or erroring.

## Reminders for Future Phases

- Do not start by rewriting notebooks blindly; preserve meaning first.
- Do not collapse research and serving concerns into one layer.
- Do not remove ambiguous intermediate datasets before documenting which ones are still needed to understand legacy behavior.
- If context is lost later, re-read all files in `instructs/` before making structural changes.
