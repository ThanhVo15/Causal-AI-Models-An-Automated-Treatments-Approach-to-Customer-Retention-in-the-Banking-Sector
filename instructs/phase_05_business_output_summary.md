# Phase 5 Business Output Summary

## Scope

Phase 5 focused on making the export package more usable for business and sales consumers without changing the underlying model behavior.

## What Now Exists

- A business-oriented Excel workbook generated by `src/causal_app/export/excel.py`
- Deterministic business output shaping in `src/causal_app/export/business_output.py`
- Real workbook sheets:
  - `Summary`
  - `Customer_Action_List`
  - `Reject_Report`
  - `Run_Metadata`
  - `Field_Definitions`
- Deterministic `priority_score` and `priority_band`
- Deterministic `reason_short`
- Human-readable reject details
- Basic workbook formatting for readability

## Fully Implemented In Phase 5

- Export workbook structure redesign
- Business-friendly action list columns
- Priority logic grounded in current engine fields
- Rule-based short reasons grounded in current engine fields
- Reject report detail mapping from validation codes
- Summary sheet with run volume, action mix, reject counts, and limitations
- Run metadata and field-definition sheets
- Real sample export generation and manual review using the archived legacy `test.csv`

## Partial

- `expected_improvement` is usable, but it still comes from the temporary legacy recommendation wrapper
- `recommended_policy` is usable for demo handoff, but it is still derived from simulated legacy policy data
- Export history is still file-backed, not Postgres-backed
- Streamlit Export page is updated to describe the new workbook, but no new UI workflow was added beyond download/access

## Deferred

- Customer value or revenue-weighted priority logic
- Confidence/support scoring beyond current `policy_support_rows`
- DB-backed export metadata history
- Additional sales-facing sheets beyond the current workbook
- LLM-generated explanations

## Important Honesty Notes

- Phase 5 did not change churn, segmentation, or recommendation math.
- `reason_short` is deterministic template logic, not GPT/LLM output.
- The recommendation layer remains traceable to the temporary Phase 3 policy wrapper and simulated legacy policy data.
- A runtime compatibility bug in the notebook-derived churn wrapper was fixed so the sample export could run under the current scikit-learn version. This was an engine compatibility fix, not a business-logic change.
